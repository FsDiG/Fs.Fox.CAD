# CAD/UI 文案风格指南

> 适用范围: `Fs.Fox.CAD`、`Fs.Lt.Shared`、`FsHoLu` 以及其他面向 CAD 用户的命令、菜单、Ribbon、WPF 弹窗和向导文案。

本文档用于统一 CAD 命令行与 UI 弹窗中的用户可见文本，方便开发者和 AI 在修正文案、评审 PR、批量清理低风险提示文本时采用一致规则。该规范是多仓库共享规范，`FsHoLu`、`Fs.Lt.Shared`、`Fs.Fox.CAD` 中的同名文档应保持同步。

## 总原则

1. CAD 命令行优先保证可读、可复制、可预测。
2. 需要用户输入或选择时，提示必须让用户明确知道下一步动作。
3. 普通状态、普通结果、普通取消不使用强烈语气。
4. 同一个提示链路内不要混用中文标点和英文标点。
5. AI 自动修正文案时，只处理低风险格式问题；涉及业务含义、按钮语义或流程变化时必须人工确认。

## CAD 命令行

CAD 命令行包含 `Editor.WriteMessage`、`PromptOptions.Message`、`PromptBuilder`、`ParameterBuilder`、关键字选项、命令执行结果等用户在 CAD 命令行看到的文本。

### 标点规则

| 场景 | 推荐标点 | 说明 |
| --- | --- | --- |
| 普通结果、普通状态、普通取消 | `.` | 例如执行完成、已取消、未找到对象、跳过处理 |
| 需要用户输入或选择 | `:` | 例如请选择对象、请输入数值、指定基点 |
| 关键字选项提示 | `:` | 选项和默认值放在冒号前 |
| 错误但不紧急 | `.` | 用清楚文本说明失败原因和下一步 |
| 强提醒 | 尽量不用 `!` | CAD 命令行避免用感叹号制造噪音，除非存在立即中断或高风险后果 |

### 格式规则

- CAD 命令行统一使用英文标点: `.`, `:`, `,`, `;`, `()`, `[]`, `< >`。
- 需要用户输入或选择的 prompt 以 `:` 结尾，不使用中文冒号 `：`。
- 不要出现重复冒号，例如 `::`、`：:`、`: :`。
- 如果公共封装函数已经追加 `:`，调用方不要再传入尾部冒号。
- 普通结果消息以 `.` 结尾，不使用 `。` 或 `！`。
- 向 CAD 命令行输出消息时，统一使用 `\n` 作为换行符，不使用 `Environment.NewLine`。
- 多条命令行消息建议以 `\n` 开头，避免和 CAD 当前提示黏在一起。
- 关键字选项与提示正文之间保留一个空格。

### 换行规则

AutoCAD .NET API 开发中，向命令行输出消息时推荐统一使用 `\n`，不要使用 `Environment.NewLine`。

原因:

- `Environment.NewLine` 在 Windows 下会输出 `\r\n`。
- 某些 CAD 宿主或版本可能把 `\r\n` 解析成多余空行，或显示异常字符。
- `Editor.WriteMessage`、`PromptOptions.Message`、Jig prompt 等命令行交互链路使用 `\n` 更稳定。

推荐:

```csharp
editor.WriteMessage("\n生成完成.");
options.Message = "\n请选择板材:";
```

不推荐:

```csharp
editor.WriteMessage(Environment.NewLine + "生成完成.");
options.Message = Environment.NewLine + "请选择板材:";
```

例外:

- 写入文件、导出文本、剪贴板内容、日志正文、MessageBox/WPF 多行文本等非 CAD 命令行输出，可以按对应场景继续使用 `Environment.NewLine`。
- 判断是否要替换时，以最终是否进入 CAD 命令行或 Prompt/Jig 文本为准。

### 推荐示例

| 场景 | 不推荐 | 推荐 |
| --- | --- | --- |
| 普通成功 | `生成成功！` | `生成成功.` |
| 普通取消 | `已取消操作！` | `已取消操作.` |
| 选择对象 | `请选择板材：` | `请选择板材:` |
| 输入数值 | `请输入偏移距离：` | `请输入偏移距离:` |
| 关键字 | `请选择板材[A/B/C]<A>:` | `请选择板材 [A/B/C] <A>:` |
| 重复冒号 | `请选择板材：:` | `请选择板材:` |
| 失败提示 | `处理失败！` | `处理失败. 请检查所选对象是否为有效板材.` |

### 关键字 Prompt

关键字 prompt 推荐结构:

```text
\n请选择处理方式 [设置(S)/取消(C)] <设置>:
```

规则:

- 正文与关键字列表之间保留一个空格。
- 关键字列表使用英文 `[]`。
- 默认值使用英文 `< >`。
- 末尾只保留一个英文冒号 `:`。
- 如果工具函数负责拼装关键字和默认值，调用方只传入正文，不传尾部冒号。

## UI 弹窗与 WPF 界面

UI 文案包含窗口标题、按钮、校验错误、确认弹窗、任务对话框、Toast、Ribbon/Menu 显示文本等。

### 标点规则

| 场景 | 推荐标点 | 说明 |
| --- | --- | --- |
| 普通提示 | `。` 或 `.` | 同一窗口、同一模块内保持一致 |
| 普通校验错误 | `。` 或 `.` | 优先说明如何修正 |
| 确认操作 | `？` 或 `?` | 同一窗口内保持一致 |
| 强提醒/破坏性操作 | `！` | 仅用于删除、覆盖、不可恢复、数据风险等强提醒 |
| 按钮文本 | 通常不用句末标点 | 例如 `确定`、`取消`、`保存`、`应用` |

### UI 规则

- 一个窗口或一个连续交互链路内不要混用 `。` 和 `.`。
- 普通提示不要使用 `！`。
- 强提醒才使用 `！`，并尽量明确风险，例如覆盖、删除、不可恢复、影响当前图纸。
- 按钮文案使用动词或明确结果，避免只有情绪化提示。
- 校验错误应说明可执行的修正方向，例如“请输入大于 0 的数值。”。
- 弹窗不要替代命令行流程中的普通状态输出；高频普通信息优先写命令行或状态区域。

## AI 自动修正规则

AI 可以自动处理:

- CAD 命令行中的中文标点替换为英文标点。
- 普通结果消息的 `！` 改为 `.`。
- CAD 命令行输出和 Prompt/Jig 文本中的 `Environment.NewLine` 改为 `\n`。
- 重复冒号清理为单个 `:`。
- 关键字 prompt 中正文和选项之间缺少空格的问题。
- 明显拼写错误、重复词、空格缺失。

AI 需要人工确认:

- 修改命令含义、菜单名称、按钮语义。
- 修改错误提示中的业务判断或修复建议。
- 把弹窗改为命令行输出，或反向修改。
- 调整窗口 modal/modeless 行为、隐藏恢复流程、事务生命周期。
- 涉及删除、覆盖、批量写图、跨文档操作等风险提示的语气和措辞。

## 评审检查清单

- CAD 命令行是否统一使用英文标点。
- CAD 命令行输出和 Prompt/Jig 文本是否使用 `\n`，而不是 `Environment.NewLine`。
- 普通结果是否以 `.` 结尾。
- 用户输入/选择提示是否以单个 `:` 结尾。
- 是否存在 `：:`、`::`、`: :` 等重复冒号。
- 关键字选项前是否有空格，例如 `请选择板材 [A/B] <A>:`。
- UI 弹窗是否在同一窗口内保持标点一致。
- `！` 是否只用于强提醒或高风险操作。
- 修改是否只改变用户可见文本格式，不改变业务逻辑。
