# CAD 通用能力增补评估（2026-08）

> 状态：已完成（Historical）<br>
> 适用范围：一次性候选代码审查、迁移取舍与验证边界<br>
> 事实来源：实时源码、`CADShared.projitems`、模块/兼容性基线和本次分支差异

## 1. 目的与原则

本次工作不是按文件复制旧工具库，而是逐项提取对 CAD 通用基础类库仍有独立价值、且能纳入当前多宿主共享源码边界的能力。判断顺序如下：

1. 先确认 `CADShared` 是否已有等价或更完整的能力；
2. 只保留不依赖业务异常、业务配置和特定 UI 文案的通用语义；
3. 公共 API 必须明确数据库、事务、宿主上下文和恢复责任；
4. AutoCAD 2014 单宿主实现不能直接推导为 AutoCAD、ZWCAD、GstarCAD 当前目标均可运行；
5. 无法在本轮说明契约或验证运行时安全性的代码不进入程序集，保留取舍结论即可。

本轮不删除或改名既有公共 API，不改变程序集、包 ID、目标框架、宿主支持矩阵、事务默认行为或 NuGet 发布流程。

## 2. 最终迁入范围

| 能力 | 最终 API | 归属 | 采用方式 |
| --- | --- | --- | --- |
| 临时系统变量 | `SystemVariableScope` | `Cad/Application/SystemVariables` | 捕获原值、设置临时值、`Dispose` 恢复；捕获创建时的活动文档，并阻止在错误文档中恢复。 |
| 临时图层解锁 | `LayerUnlockScope` | `Cad/Database/SymbolTables` | 通过明确的 `ObjectId` 或 `Database + layerName` 解锁并恢复锁定状态。 |
| 动态块参数读取 | `BlockReferenceEx.TryGetBlockProperty` | `Cad/Database/Entities/Blocks` | 与现有 `ChangeBlockProperty` 配对，保留原生 `object` 值，不引入不完整的参数对象体系。 |

### 2.1 有意缩小的边界

- `LayerUnlockScope` 不处理 `IsFrozen`。冻结状态受当前图层和视口语义约束；通用 `Dispose` 无法保证调用期间图层成为当前图层后仍能无副作用地恢复冻结状态。
- `SystemVariableScope` 不自动切换活动文档。系统变量可能是文档级状态；释放时若活动文档与创建时不同，将抛出 `InvalidOperationException` 且保持未释放状态，调用方恢复原文档上下文后可以重试。
- 动态块读取只增加单值 `TryGet`。不迁入字符串化参数模型、读写器接口或只支持非负 `double` 的业务校验。

## 3. 逐组审查结论

| 候选组 | 结论 | 主要依据 |
| --- | --- | --- |
| 活动文档、编辑器、数据库快捷入口 | 不迁入 | `Env` 已提供同类上下文；增加第二套静态入口会扩大空值和非模态（modeless）上下文歧义。 |
| 数据库访问器与文件数据库保存 | 不迁入 | `DBTrans`、`SwitchDatabase` 和现有文件数据库入口覆盖核心场景；候选实现还包含反射修改异常、临时文件替换和隐式 WorkingDatabase 切换。 |
| 系统变量切换器 | 迁入并重设计 | 作用域恢复模式通用且现有代码缺少对应 API；新增实现补充幂等释放和上下文契约。 |
| 图层解锁器 | 部分迁入并重设计 | 临时解锁有通用价值；隐式 WorkingDatabase 和解冻/复冻行为不进入新契约。 |
| 动态块读写器及参数接口 | 仅迁入读取意图 | 现有 `BlockReferenceEx` 已能写参数、读属性和取有效块名；候选参数体系存在未实现方法，并把所有值降为字符串。 |
| 视图缩放 | 不迁入 | `EditorEx` 已提供 `Zoom`、`ZoomWindow`、`ZoomExtents` 和 `ZoomObject`，且已处理当前视图坐标变换。 |
| 多实体 Jig | 不迁入 | `JigEx` 已覆盖动态实体队列、UCS 输入、关键字、动态标注和跨宿主绘制差异。 |
| DWG 反向引用扫描 filer | 本轮不迁入 | 思路有价值，但依赖 `DwgOut` 回调、完整抽象成员实现及各宿主序列化行为；已关闭的 [Issue #35](https://github.com/FsDiG/Fs.Fox.CAD/issues/35) 记录了暂不迁移的历史决策。 |
| 本地/全局 XML 配置 | 不迁入 | 不属于 CAD SDK 基础能力；程序集目录写入、反序列化失败即删文件以及反射合并属性都不适合作为通用默认策略。 |
| 计时器和业务异常 | 不迁入 | `Stopwatch` 封装过薄；异常类型承载特定业务分类，缺少可复用契约。 |
| TaskDialog、通知气泡、Palette 文本框 | 不迁入 | 依赖 AutoCAD 专用桌面组件或实现不完整，且没有 ZWCAD/GstarCAD 的一致 UI 契约。 |
| 按包围盒识别文本列/表 | 本轮不迁入 | 能力方向有价值，但当前算法未处理旋转文字、UCS、容差、合并单元格和文字顺序；应先建立确定的数据模型与样例图。 |

真实 CAD 宿主为 `Not run`。构建通过只证明托管 API 签名和条件编译在当前 SDK 下成立，不能证明系统变量、图层状态或动态块行为已经通过 AutoCAD/ZWCAD/GstarCAD 真实会话验收。

### 4.1 后续真实宿主人工验收清单

以下步骤记录未来需要执行的行为验收，不作为本次合并门槛。优先在 ZWCAD 2022 执行，再按实际发布需要覆盖 AutoCAD 2020；每次都应记录 CAD 产品、完整版本、编译目标和测试程序集。

1. `SystemVariableScope`：选择可安全恢复的数值型变量，分别验证正常退出、作用域内抛异常和重复 `Dispose` 后均恢复原值，并确认恢复值的运行时类型未改变。
2. `SystemVariableScope` 多文档保护：在文档 A 创建作用域后切换到文档 B，确认 `Dispose` 抛出 `InvalidOperationException` 且文档 B 的变量未被改写；切回文档 A 后重试并确认恢复成功。
3. `LayerUnlockScope`：对锁定图层分别通过 `ObjectId` 和 `Database + layerName` 创建作用域，验证正常退出和异常退出均恢复原锁定状态；同时覆盖图层对象已经写打开的嵌套事务场景。
4. `BlockReferenceEx.TryGetBlockProperty`：使用包含数值和文本参数的动态块，验证精确名称读取、大小写不匹配、非动态块返回值及 SDK 原始值类型。

## 5. 后续规则

- 需要加入解冻/复冻作用域时，必须先定义当前图层切换、视口冻结、多文档切换和释放失败的行为，再建立独立 Issue/PR。
- 需要加入 DWG 引用扫描时，新建独立 Issue 并关联历史 [Issue #35](https://github.com/FsDiG/Fs.Fox.CAD/issues/35)；新工作仍须明确消费者、状态机和宿主往返验证门槛。
- 需要识别散落文字表格时，先提供覆盖旋转、容差和合并单元格的代表性 DWG/期望结果，再设计独立数据模型。
- 后续维护以实时 C# XML 注释、项目清单和兼容性基线为准；本文只追溯本轮取舍，不作为长期开发计划。
