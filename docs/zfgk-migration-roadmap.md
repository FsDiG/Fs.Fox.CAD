> 受众：维护者、迁移负责人、复核者<br>
> 复核日期：2026-10-25<br>
> 目标基线：Fs.Fox.CAD `main` @ `5729ef6e97a4f0e0f4132da86fd75495b2003079`<br>

本文用于确定迁移方向、阶段顺序和责任边界，支持按能力领域分派工作。用户已于 2026-10-25 批准实施；具体 API 在各工作线启动时收敛。完整来源处置和依赖见[能力清单](zfgk-migration-inventory.md)，实现与验证完成情况分别记录。

## 1. 迁移目标与前一版建议的调整

目标是把 Zfgk 中有复用价值、能补齐 Fox 能力的部分，逐步纳入 Fox 的现有模块、宿主适配和维护体系。迁移单位采用“能力”，保留原作者及来源记录，并逐项识别外部依赖与已知问题。

| 前一版建议 | 复核后的调整 |
| --- | --- |
| 优先迁移多段线整理、块或实体排序 | 保留为试点方向；具体范围按需求、已有能力和风险收敛，不承诺整类迁入。多段线连接涉及更多几何及所有权问题，可在基础整理之后推进。 |
| 按原工具类安排迁移 | 按几何处理、排序、文字、表格等能力领域组织，避免把原库的结构和隐含依赖一并引入。 |
| 加上 Beta 表示未正式测试 | 保留 Beta 标记，同时独立记录静态审查、构建和实际宿主证据；名称本身不能证明完成程度。 |
| 一边迁移一边安排大量细任务 | 先确定阶段目标和责任人；仅在进入该阶段时细化接口、文件及验证场景。 |
| 转正后保留 Beta 转发入口 | 是否保留及保留多久，由实际调用方和发布兼容要求决定，不预先承诺永久兼容层。 |

## 2. 能力优先级

当前价值判断来自源码对照，尚未包含产品调用频率或真实图纸统计。第一阶段需要用代表性使用场景校准优先级。

| 工作线 | 能力方向 | 推进原则 |
| --- | --- | --- |
| A | 多段线整理、连接与方向处理 | 几何计算与数据库写入分开，保留圆弧、宽度和坐标平面；复用已有采样、段长和圆角入口。 |
| B | 沿曲线、按行列排序，邻近范围组合 | 明确稳定排序、容差分组和范围语义；返回计算结果，不修改输入数据库。 |
| C | 文字样式测量、块属性能力对照 | 补齐按样式测量字符串；属性读写复用现行 API，避免重复的简单属性封装。 |
| D | 三角形计算、多面网格构造与标注能力对照 | 明确坡度、坡向单位及退化输入，严格检查网格面索引；标注薄封装复用 SDK 和现行落库能力。 |
| E | DWG 图片预览 | 以 AutoCAD 原有渲染路径为基础，明确外部文件、活动宿主和图形资源生命周期；其他宿主单独标记支持范围。 |

全局能力清单先确定，再按五条工作线并行实施和滚动集成。Zfgk 自绘表格及其专用模型、布局、合并和绘制业务按用户决定排除；业务断面、植物结果窗口、图纸比例业务及重复空间索引也排除。事务、符号表、选择集、XData 等优先复用 Fox。

## 3. 阶段顺序与推进条件

| 阶段 | 主要目标 | 进入下一阶段的条件 |
| --- | --- | --- |
| 范围校准 | 核对实际使用场景、Fox 覆盖程度、原库缺陷与外部依赖；明确 Beta 和支持范围约定 | 试点能力能够说明使用者、收益、边界和负责人；来源与授权记录可追溯，主要依赖有处理方向。 |
| 并行细化与实现 | 五条工作线分别收敛接口、副作用、所有权、宿主和验证场景，再实现选定能力 | 各线有可独立评审的实现、生产核心回归或宿主命令及使用说明。 |
| 滚动集成与回归 | 逐项导入已复核能力，协调共享编译清单和模块基线，进行七目标 Debug/Release 检查 | 生产核心回归、模块校验和构建通过，来源处置完整，文档和实际支持范围一致。 |
| 验收与转正 | 在后续明确执行验证时，按声明支持范围取得实际证据，评估正式入口及兼容迁移 | 相应自动检查与真实宿主场景均有可追溯结果，接口和行为达到转正标准；未覆盖宿主不作通过承诺。 |

表格业务保持排除。DWG 预览为独立工作线，不依赖其他四条工作线的新 API，也不扩大非 AutoCAD 宿主的支持承诺。

构建边界已经用户明确：Fs.Zfgk.CAD 只作静态来源，不再构建；Fs.Fox.CAD 正常构建并执行自动检查，覆盖现行七个发布目标的 Debug/Release。实际 CAD 宿主验收单独记录，遵守根协作规则中的隔离要求；未执行项保持 `Not run`。

### 按影响范围选择验证

后续采用增量验证，不在每次修正后重复整套构建。统筹人先识别实际改动及其依赖，再选择检查；结果仍有效且代码未受影响的检查直接沿用。

| 改动 | 默认验证 | 扩大检查的条件 |
| --- | --- | --- |
| 文档、索引、说明 | diff、受影响相对链接和 GFM 渲染 | 链接移动或公共说明跨册变化时扩大文档检查，不触发编译。 |
| SDK 无关的数值核心 | 对应生产链接回归与独立反例 | 公共签名、语言/框架能力变化时，补 net48/net8 代表目标。 |
| CAD 对象适配或条件编译 | 受影响的厂商/API 绑定及相关宿主命令编译 | 新增或改变跨宿主分支时扩大到相应目标，不重跑无关厂商。 |
| 共享编译项、TFM、SDK 或发布依赖 | 相关模块校验和实际受影响目标 | 无法可靠限定影响，或达到整体集成交付里程碑时，运行七目标完整矩阵。 |

真实 CAD 运行按具体风险场景单独安排。完整矩阵作为集成里程碑证据保留；收尾小修按上表补充证据，不重复还原依赖和无关编译。现有 CI 的正式检查不随本地增量策略降低。

## 4. 宏观分工

| 角色 | 主要责任 | 交接结果 |
| --- | --- | --- |
| 统筹与集成负责人 | 维护范围、优先级、公共约定和支持边界；协调跨领域依赖；统一处理共享编译清单、模块校验和文档入口 | 一致的集成结果及明确的已完成、待验证项。 |
| 能力迁移负责人 | 按能力领域完成源码对照、方案收敛、实现及相关注释；处理本领域已确认缺陷 | 可独立评审的能力变更，附来源、行为边界及验证证据。 |
| 独立复核负责人 | 复核与既有能力的重复、行为正确性、对象归属、宿主差异和证据是否充分 | 有依据的接收或返修意见；区分静态结论与尚待执行的验证。 |

分工遵循以下原则：

- 不同能力领域可以并行，同一组紧密关联的几何操作由同一负责人统筹。
- 公共约定先对齐，再进入依赖它的实现；不要求提前设计完所有后续能力。
- 共享项目清单和模块校验由集成人协调，每个能力的集成变更仍随该能力一并评审，避免遗漏编译项。
- 以能力为单位形成短期分支和 PR，便于审查、反馈及回退。
- 角色是责任划分，不要求固定人数；复核应与实现形成独立检查。

## 5. Beta 与宿主边界

采用 Beta 后缀。普通类型在类型名体现；扩展方法应在调用位置体现试验状态。沿用 Fox 的现有模块、`Fs.Fox.Cad` 命名空间和程序集组织，不新增 ZFGK 二进制依赖。

Beta 表示接口仍处于迁移和验证阶段。已知错误仍须处理；现有稳定入口不自动改为依赖 Beta。转正依据是该能力声明范围内的实际证据及接口稳定程度。

每项能力至少区分以下状态，而不是用单个“完成”覆盖全过程：

| 证据维度 | 需要回答的问题 |
| --- | --- |
| 静态审查 | 来源、依赖、边界、对象归属及已确认缺陷是否检查清楚？ |
| 编译与自动检查 | 实际执行了哪些目标和检查，针对哪个提交，结果是什么？ |
| 宿主验收 | 在哪个 CAD 产品和完整版本中执行了哪些场景？哪些仍为 `Not run`？ |

同一份共享源码被多个项目引用，不等于已经适配并验收所有宿主。具体支持范围应随能力明确，复用现有宿主别名和边界；不能仅替换 AutoCAD 命名空间就宣称多宿主可用。

集成遵循 Fox 的正常工作流。共享编译清单、模块数量和源码哈希基线由集成人统一协调；纯计算部分优先使用直接引用生产核心代码的自动测试，CAD 命令测试和真实宿主运行分别记录。

## 6. 支撑本计划的当前证据

- [Zfgk 多段线源码](https://github.com/FeiSiDev/Fs.Zfgk.CAD/blob/a882003436fb4cc31b24c90f6779177c13a60abe/ObjectARX/Entity/PolylineUtil.cs)：连接路径会释放第二条输入曲线；清理顶点路径按点集重建。迁移前需要重新明确所有权与圆弧、宽度的保留边界。
- [Zfgk 块排序源码](https://github.com/FeiSiDev/Fs.Zfgk.CAD/blob/a882003436fb4cc31b24c90f6779177c13a60abe/ObjectARX/Entity/BlockUtil.cs)：沿曲线排序通过扰动重复距离构造字典键；坐标排序比较器包含相等时仍返回非零值的路径。排序能力需要重新审查比较规则。
- [Fox 多段线现行实现](../src/CADShared/Cad/Database/Entities/Curves/Polylines/PolylineEx.cs)已包含顶点数据、段长和采样；[几何源码导航](source-navigation/geometry.md#todo)明确标注未编译 ToDo，避免把它们视为现行公共功能。
- [共享源码模块校验](../Build/Verify-CADSharedModuleMap.ps1)目前固定总编译文件数及模块数量。新增能力涉及显式编译项和对应校验，不能仅复制源文件。
- [TypeDef 序列比较工具](../tools/verification/Compare-CADSharedTypeDefSequence.ps1)用于严格比较已构建程序集的类型序列；本次功能新增不应套用“类型序列完全不变”的纯移动验收标准，也不能通过修改工具掩盖有意新增的 API。
- [宿主验收说明](../tools/HostAcceptance/README.md)、[根协作规则](../AGENTS.md)和[构建工作流](../.github/workflows/build-and-deploy.yml)分别约束实际运行证据、宿主使用边界及触发行为。

本路线图、能力清单和文档入口已先独立提交为 `25a573c`。五条工作线已完成 Beta 源码集成和自动检查；当前使用入口见 [Beta 总览](guides/zfgk-beta.md)，实际结果见[验证记录](zfgk-migration-inventory.md#验证记录)。后续真实宿主验收和转正按明确的验证任务继续推进，不能从本次自动检查推断通过。
